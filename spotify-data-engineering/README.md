# Spotify Data Engineering Project

End-to-end Azure Data Engineering project demonstrating ingestion, orchestration, incremental processing, transformation, data quality, dimensional modeling, CDC/SCD processing, business analytics, and deployment using Azure Data Factory, ADLS Gen2, Azure Databricks, PySpark, Delta Lake, Delta Live Tables, and Databricks Asset Bundles.

## Architecture

```text
Source
   ↓
Azure Data Factory
   ↓
Bronze (ADLS Gen2)
   ↓
Silver (Databricks / Delta)
   ↓
Gold (Delta Live Tables)
   ↓
Analytics
```

## Incremental Processing

The ADF pipeline uses metadata/control information to determine the
incremental processing window and avoid unnecessary full reloads.

Typical flow:

```text
Lookup Metadata
      ↓
Determine Incremental Window
      ↓
Check New Data
      ↓
Process New Data
      ↓
Update Metadata
```

## Databricks Processing

Bronze data is processed with PySpark and Auto Loader.

Example pattern:

```python
df = (
    spark.readStream
        .format("cloudFiles")
        .option("cloudFiles.format", "parquet")
        .option("cloudFiles.schemaLocation", "<SCHEMA_LOCATION>")
        .load("<BRONZE_PATH>")
)

(
    df.writeStream
        .format("delta")
        .option("checkpointLocation", "<CHECKPOINT_LOCATION>")
        .option("path", "<SILVER_PATH>")
        .outputMode("append")
        .start()
)
```

Schema locations and streaming checkpoints are intentionally represented
as placeholders in this portfolio version.

## Gold Layer

The Gold layer is implemented using Delta Live Tables and contains
dimensional, transactional, and business-oriented analytical tables.

### Dimension and Fact Tables

The curated Gold model includes:

* `dimuser`
* `dimartist`
* `dimtrack`
* `dimdate`
* `factstream`

These tables provide the foundation for analytical reporting.

### Business Analytical Tables

Two business-facing analytical tables are also implemented:

#### Daily Streaming Summary

`daily_streaming_summary` provides daily streaming metrics including:

* Total streams
* Unique users
* Unique artists
* Total listening duration
* Average listening duration
* Latest stream timestamp

The table is generated by joining `FactStream` with the relevant
dimensions and aggregating data at the daily grain.

```text
FactStream
    ↓
DimTrack + DimDate
    ↓
Daily Aggregation
    ↓
daily_streaming_summary
```

#### Artist Performance

`artist_performance` provides artist-level performance metrics including:

* Total streams
* Unique listeners
* Total listening duration
* Average listening duration
* Latest stream timestamp

The aggregation uses:

```text
FactStream
    ↓
DimTrack
    ↓
DimArtist
    ↓
Artist Aggregation
    ↓
artist_performance
```

For SCD Type 2 dimensions, current records are selected using:

```python
.filter("__END_AT IS NULL")
```

This prevents historical dimension versions from causing duplicate
joins in current-state analytical reporting.

## SCD

The project demonstrates:

* **SCD Type 1** for maintaining the latest dimension state.
* **SCD Type 2** for retaining historical dimension versions.

SCD Type 2 dimensions maintain historical records using effective
start/end timestamps. Current records can be identified using:

```text
__END_AT IS NULL
```

## Data Quality

Delta Live Tables expectations are used to validate required fields
and control invalid records before they reach analytical tables.

Data quality rules are applied during Gold-layer processing to help
prevent invalid records from propagating into analytical datasets.

## Dimensional Modeling

The Gold layer follows a dimensional modeling approach:

```text
                 DimUser
                    │
                    │
DimDate ─────── FactStream ─────── DimTrack
                                      │
                                      │
                                  DimArtist
```

`FactStream` acts as the central fact table, while the dimension tables
provide descriptive attributes used for analytical reporting.

Business aggregates are then created from the dimensional model for
common analytical use cases.
